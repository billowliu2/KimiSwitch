# KimiSwitch v0.8.8

模型思考等级 + kimi-code 2.3.1 适配版：两个数据安全修复、思考等级列，以及 2.3.x 新字段的界面适配。

## 思考等级（新功能）

- 模型表新增「思考等级」下拉列（kimi-code 专属）：档位优先取模型自身 `support_efforts`，其次 models.dev 能力数据；默认 **high**，模型不支持 high 时自动取其最高档
- models.dev 同步新增 `reasoning_options` 解析（efforts / off 档 / toggle 开关），快照重新生成（8,872 模型 / 230 提供商）
- 批量添加模型、应用供应商预设、同步或恢复 models.dev 数据后，自动补齐能力标记与思考等级（保存时写入 `[models.*] default_effort`）
- 修复 models.dev 前缀 id（如 `commandcode/deepseek-v4.1-flash`）匹配不到参考数据的问题

## 数据安全修复（高危）

- **保存不再抹掉 CLI 写入的 provider / model**：kimi-code 2.3.x 的模型目录定时刷新（默认 6h + 启动时）、catalog 引导、`/provider refresh` 都会直接写 config.toml，此前 KimiSwitch 任何一次保存都会整表覆盖、静默抹掉这些新增条目。现保存时与磁盘做并集合并：CLI 新增的条目保留，你在 UI 里删除的仍然删除
- **provider 级 `default_model` 不再丢失**：它是 kimi-code 官方字段（catalog 引导会写入），此前被误当作 KimiSwitch 私有键在保存时剥除。现原样往返读写；SQLite 里的旧记忆值仅在 config.toml 缺失该键时兜底，不再反向覆盖 CLI 的改动

## kimi-code 2.3.x 新字段适配

- 新增「禁用反馈调查」开关（`disable_feedback_survey`，2.3.0 从 tui.toml 迁入 config.toml 顶层；仅勾选时写入 `true`，未勾选不落盘）
- 模型行新增 upgrade「将停用」只读标记：琥珀色小标签，悬浮显示建议迁移目标与停用日期
- 「危险命令防护」文案更正：自 2.3.0 起该开关同时门控危险命令、敏感文件访问、.git 路径访问三类防护（原文案只提了危险命令）

## 其他

- 全局 `[thinking] effort` 未显式设置时不再写死 `medium`，不再压过模型级 `default_effort`（此前每次保存都会物化全局 medium，把模型级 high 盖掉）
- models-dev 快照引入 `schema_version = 2`：旧格式的运行时同步副本（无思考等级数据）不再遮住内置快照——旧副本会被忽略并改用内置数据，在设置页点一次「立即同步」即写成新格式
- `model_source`、`custom_headers`、`[mcp] default_deferred` 等新字段经 raw_other 透传保持不变
